# Structurelint

Structurelint checks an existing project's files and folders against rules you define, and reports every entry no rule allows and every required one that is missing. It is a CLI and a JavaScript API, it does not need ESLint, and it never scaffolds or generates code: it only reads what is on disk.

> Content is verified against **`@ladamczyk/structurelint` v1.1.6**. See [`CHANGELOG.md`](https://github.com/ladamczyk-it/structurelint/blob/main/CHANGELOG.md) to verify accuracy.

## Why

Folder structure is architecture, and code review is a poor place to enforce it. AI coding agents make it harder still: they create files wherever the task is easiest. Describe the layout once as rules, and every run, local, in CI or after an agent's change, fails on a stray `utils2.ts` or a component without its `index.ts`.

```ts
// structure.config.ts
import type { IStructureConfig } from '@ladamczyk/structurelint';

export default {
  structureRoot: 'src',
  structure: [
    { name: 'index.ts', required: true },
    { name: 'components', children: [{ name: '{PascalCase}.tsx' }] },
  ],
} satisfies IStructureConfig;
```

Rules are **recursive**: a rule can reference itself or other named rules to describe nested structures, such as `components/Button/nested/Icon`, where `nested` reuses the same PascalCase component rules as the root `components`. See [Rules](./rules.md).

## Installation

```bash
npm install --save-dev @ladamczyk/structurelint
npx structurelint
```

Or run it directly without installing:

```bash
npx @ladamczyk/structurelint
```

It needs Node `^22.22.2`, `^24.15.0` or `>=26` and npm 10 or later. `.ts` configs also need `typescript` in your project.

## Compared with similar tools

|                              | structurelint                                    | ls-lint                                  | eslint-plugin-project-structure                          |
| ---------------------------- | ------------------------------------------------ | ---------------------------------------- | -------------------------------------------------------- |
| What it validates            | which files and folders may exist at each level  | file and directory names                 | folder structure, imports between modules, file contents |
| Required files and folders   | yes, `required: true`                            | counts per directory with `exists:N`     | yes, when a related file exists                          |
| Reusable and recursive rules | yes, with a recursion limit                      | glob keys and parent-folder substitution | yes, with a depth limit                                  |
| Needs ESLint                 | no                                               | no                                       | yes                                                      |
| Config                       | `structure.config.ts` (or `.js`, `.mjs`, `.cjs`) | `.ls-lint.yml`                           | ESLint config                                            |

ls-lint is the pick when only names matter; eslint-plugin-project-structure when the structure check should live inside ESLint alongside import rules. Structurelint was extracted from an ESLint structure rule so the check runs **in parallel** with the rest of your tooling, outside the ESLint pipeline.
